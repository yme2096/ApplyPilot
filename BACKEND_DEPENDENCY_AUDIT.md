# Backend Maven Dependency Security Audit

**Audit date:** 2026-11-03
**Status:** Scan **PASS**; remediations **PASS**; two narrowly scoped Spring risks **ACCEPTED / OPEN**. This is a dependency scan, not a penetration test or production-readiness approval.

## Method and scope

- OWASP Dependency-Check was attempted first, but its NVD dataset update did not complete without an NVD API key and it produced no report. No key was present in the environment, and no key was printed or written.
- Fallback: Trivy **0.76.1**, obtained from the official release and checksum-verified. The vulnerability database completed its update. A CycloneDX **1.6** SBOM was generated by Maven CycloneDX plugin **2.9.1** with test scope enabled; it contains **122 components**. Trivy's JSON report is a completed scan of that SBOM.
- The Maven dependency tree includes compile, runtime and test paths. `spring-webmvc` is a transitive runtime dependency of the declared `spring-boot-starter-web`; it is not declared directly.
- Full reports, SBOM, dependency tree and CSV findings are stored under the Git-ignored `security-reports/` directory. The full report is generated without ignore rules; the policy scan uses only the two expiring entries described below.

## Remediations applied

`backend/pom.xml` now uses Spring Boot **3.5.16** and keeps Java **21**. Spring's 3.5.16 system requirements accept Java 17 through Java 25 and require Spring Framework 6.2.19 or later. Compatible patched BOM properties were set for Jackson **2.21.7**, Log4j **2.25.5**, Netty **4.1.139.Final**, PostgreSQL JDBC **42.7.12**, and Tomcat **10.1.61**. These are dependency-management overrides, not application-code rewrites. The completed post-change scan found no remaining findings for these components.

## Remaining findings and risk decisions

| Dependency / installed version | Finding / severity | Directness and path | ApplyPilot relevance | Fixed version and safe-upgrade assessment |
|---|---|---|---|---|
| `org.springframework:spring-webmvc` **6.2.19** | **CVE-2026-47884**, Trivy/GHSA CVSS **9.8 Critical** | Transitive, runtime via `spring-boot-starter-web` | The advisory's exploit requires `XsltView` plus a catch-all mapping that renders a view without an explicit view name. Source inspection found no `XsltView`, `ModelAndView`, or catch-all view-rendering controller; the app exposes REST APIs. The vulnerable library remains present, so this is an accepted residual dependency risk, not a claim the library is fixed. | Trivy lists **7.0.9**; that requires the Spring Framework 7 / Spring Boot 4 generation. Spring's 6.2.20 fix is listed as Enterprise Support only. No safe free Spring Boot 3.x patch fixing this advisory was identified. The application-level preconditions are absent; retain an expiring exception and reassess before expiry or any MVC/view feature. |
| `org.springframework:spring-webmvc` **6.2.19** | **CVE-2026-47890**, Trivy labels **Critical**; sources disagree (GHSA CVSS 9.8, Red Hat 6.5; Spring's advisory rates it **Low**) | Transitive, runtime via `spring-boot-starter-web` | Requires Spring MVC/WebFlux to stream view fragments through SSE with attacker-controlled data. Source inspection found no SSE emitters, `text/event-stream` handlers, or view-fragment streaming. No relevant endpoint is implemented. | Trivy lists **7.0.9**; 6.2.20 is Enterprise Support only per the Spring advisory. A Spring Boot 4 / Framework 7 migration is a major upgrade and was not treated as a safe focused patch. Keep an expiring exception and reassess if SSE/view fragments are introduced. |

Exceptions in root `.trivyignore` are limited to these CVE IDs and expire **2027-02-01**. The unfiltered JSON report retains both findings. The CI policy scan fails on other HIGH/CRITICAL findings and passes only while these documented exceptions remain valid. They must be removed if fixed dependencies become safely available, the exception expires, or the relevant application features are introduced.

## Verification

- **PASS:** Maven `verify` on Java 21 with Spring Boot 3.5.16; **68 tests, 0 failures, 0 errors, 0 skipped**; repackaged backend JAR produced.
- **PASS:** Trivy report parses and contains **122 SBOM components**; final unfiltered findings: **2 Critical by Trivy, 0 High, 0 Medium, 0 Low**. The vendor Spring advisory rates CVE-2026-47890 Low, as noted above.
- **PASS:** Trivy HIGH/CRITICAL policy check with the two expiring, documented risk exceptions returned exit 0. This is not a zero-findings scan.
- **IMPLEMENTED / NOT TESTED:** The GitHub Actions workflow is added, but no hosted GitHub Actions run was triggered. Its Maven/SBOM/Trivy steps and the ignore policy were exercised locally; hosted artifact upload and CI permissions remain untested.
- **PASS:** Frontend tests **20/20** and production build; extension tests **20/20** and production build.
- **PASS:** Docker Compose configuration validation; existing services were healthy and `/api/health` and web returned HTTP 200. Existing PostgreSQL, Redis and resume volumes remain present. No restart, migration, database write, or volume operation was performed for this audit.
- **BLOCKED at final recheck:** The Docker engine named pipe became unavailable and subsequent localhost API/web checks did not connect. No restart was attempted. The earlier HTTP 200/healthy checks are valid observations from before that change; current service health cannot be confirmed.
- **NOT TESTED:** Primary database row counts were not re-queried in this pass; no database command or write was performed. Last recorded full count comparison remains the earlier isolated restore drill.
- **NOT TESTED:** The running Compose API was not rebuilt/restarted to activate this new Maven dependency set, by the instruction to preserve running services. Live HTTP health therefore validates the existing running stack; upgraded-library behavior is covered by the backend test/package build, not a newly activated container. Browser Chrome, live Ollama, penetration testing and production deployment remain outside this audit.

See `security-reports/trivy-backend-all.json` for the complete machine-readable findings, `security-reports/applypilot-backend-all.json` for the SBOM, and `security-reports/maven-dependency-tree.txt` for dependency paths. The report directory is ignored by Git by design; CI uploads equivalent JSON reports as an artifact.
